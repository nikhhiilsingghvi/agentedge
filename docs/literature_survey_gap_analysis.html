Paper-By-Paper Analysis · 6 References
01 / 06 ICLR 2024

AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation

Wu et al. · Microsoft Research / Penn State

▪ Conversation-driven multi-agent orchestration paradigm.
▪ Strict role separation between planner, executor, and critic.
▪ 5-phase loop blueprint for autonomous agent execution.
▪ Modular architecture for pluggable agent personas.
Dimension Their Work AgentEdge
Environment Cloud server / Cluster Offline Raspberry Pi 5 (8GB)
Sensors None (pure digital APIs) 5 industrial sensors (DHT22, MQ-2, etc.)
Resource mgmt None (unbounded compute) RAD (Novel #1: Step splitting)
Failure Not addressed (100% uptime) 4-type taxonomy & matrix (Novel #2)

“AutoGen taught us how to structure agent conversations — AgentEdge applies it on constrained hardware with real sensor tool-use.”

02 / 06 ICLR 2023

ReAct: Synergizing Reasoning and Acting in Language Models

Yao et al. · Princeton / Google Research

▪ Interleaved Thought → Action → Observation execution trace.
▪ Explicit reasoning traces significantly reduce action hallucination.
▪ Grounding external tool execution directly into prompt context.
▪ Foundational control loop design for interactive autonomy.
Dimension Their Work AgentEdge
Action space Web search / text Wikipedia Physical GPIO relays, buzzer, indicator LEDs
Observation Web APIs & static text buffers Real-time analog/digital sensor readings
Constraints Cloud LLMs (PaLM 540B / GPT-4) On-device SLM (Gemini Flash / Quantized edge)
Benchmarks HotpotQA & ALFWorld AgentEdge-Bench (Novel #3: 20 tasks)

“ReAct gave us the Thought-Action-Observation loop — applied to physical control with real sensor grounding.”

03 / 06 arXiv 2025

A Taxonomy & Architecture of Agentic AI on Embedded Edge

Rüb & Gerhards · arXiv:2606.02862

▪ Tiered edge-agent taxonomy from microcontrollers to edge gateways.
▪ Explicit separation of governance, safety, and operational layers.
▪ Formal latency/energy trade-off characterization for edge models.
▪ Architectural blueprint for embedded autonomous agents.
Dimension Their Work AgentEdge
Type Conceptual survey only Fully implemented, running physical system

Recovery Failure modes identified unhandled Formal 4-type recovery taxonomy (Novel #2)

“They describe what an embedded agent should look like — AgentEdge builds it, runs it, and measures it.”

▪ Dual pipeline combining lightweight YOLOv5n with SLM planner.
▪ Strict 5W operational power target feasibility on edge.

Our Three Novel Contributions

Bridging the critical gap between cloud-scale agent theory and physical edge execution.

Novel Contribution 1

#1 Resource-Adaptive Task Decomposition (RAD)

Continuous telemetry monitor tracking RAM (71.6% peak threshold) and CPU throttle. Dynamically decomposes monolithic multi-step plans into atomic single-action execution steps when resource starvation is detected. No existing edge literature implements runtime dynamic decomposition.

Fills gap in: AutoGen Rüb & Gerhards ATLASv2 Qin et al.
Novel Contribution 2

#2 Sensor Failure Recovery Protocol

Formal fault taxonomy classifying hardware faults into TIMEOUT, BAD_DATA, DISCONNECT, and BUS_ERROR. Coupled with a deterministic RETRY / SKIP / ABORT decision matrix and peripheral reset routines, achieving a verified 50% automated recovery rate on embedded hardware.

Fills gap in: ReAct Rüb & Gerhards ATLASv2 Belcak et al.
Novel Contribution 3

#3 AgentEdge-Bench: 20-Task Benchmark

The first standardized benchmark purpose-built for embedded agentic AI. 20 real hardware scenarios spanning 4 task categories (Nominal Monitoring, Thermal Threshold, Gas Leak Alert, Sensor Degradation) evaluating planning latency, token efficiency, and recovery success against synthetic web benchmarks like HotpotQA and ALFWorld.

Fills gap in: ReAct Belcak et al. Rüb & Gerhards
“None of the above works address the combination of: (a) real sensor tool-use, (b) runtime resource adaptation via RAD, (c) formal sensor failure recovery with a 4-type taxonomy, and (d) a standardized embedded agentic benchmark — which is exactly the gap AgentEdge fills.”
