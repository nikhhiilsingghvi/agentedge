Slide 3: The Core Problem  AI agent systems like ChatGPT, LangGraph, and AutoGen are powerful - but they run entirely on cloud servers. They need internet, powerful GPUs, and constant connectivity. Real-world embedded systems - factory sensors, medical monitors, agricultural nodes - need intelligence that works offline, on cheap hardware, in real-time. Existing work has explored edge LLMs, embedded AI agents, and physical tool interaction, but unified empirical evaluation of agentic task execution under resource constraints and hardware failures remains limited. Slide 5: PROBLEM STATEMENT  Current agentic AI systems are primarily designed for powerful cloud-based environments. Embedded devices introduce constraints such as limited memory, CPU capacity, and unreliable hardware tools. Under these conditions, an agent may experience slower execution, failed tool calls, incomplete plans, or incorrect responses. The impact of these constraints on agentic AI task execution and reliability remains insufficiently characterized.  Four Specific Sub-Problems P1 - RAM Overflow Mid-Task: When the agent plans a complex multi-step sequence, available RAM on RPi5 may be exhausted mid-execution. Existing embedded-agent approaches provide limited evaluation of mid-task resource exhaustion and recovery. P2 - Sensor Failure During Execution: Physical sensors can disconnect, timeout, or return invalid data during execution, requiring the agent to detect the failure and recover. P3 - No Embedded Agent Benchmark: Zero standardized benchmarks exist for agentic AI on embedded hardware. Researchers have no baseline to compare against. P4 - SLM Performance Unknown at Edge: The latency, memory, energy and task-success trade-offs of different SLMs for agentic tasks on RPi5 require further empirical characterization.
Slide 6: OBJECTIVE Deploy SLM on RPi5 Offline: Run TinyLlama 1.1B and Phi-3-Mini 3.8B (4-bit GGUF) via llama.cpp on Raspberry Pi 5 with zero cloud dependency Build Complete Agent Loop: Implement Perceive → Plan → Execute → Verify → Recover loop in Python with 5 real sensor/actuator tools (GPIO, camera, BLE). Resource-Adaptive Decomposition: Design and implement an algorithm that monitors live RAM/CPU usage and splits plan steps into sub-tasks when resources are constrained. Sensor Failure Recovery Protocol: Formally define and implement failure classification (timeout / bad reading / disconnect) with automated recovery actions. AgentEdge-Bench: 20-Task Suite: Create the first standardized benchmark for embedded agentic AI - 20 tasks with ground-truth success metrics, publishable as a research artifact. Measure Latency / RAM / Energy: Characterize all agent components: tokens/sec, RAM per planning step, mJ per decision using INA219 current sensor on real hardware.
